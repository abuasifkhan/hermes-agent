# AKKA/Fideum Session Pattern — 2026-05-20

## What this reference preserves

Asif asked to preserve the AKKA-style company writeup pattern after a Fideum deck/screenshot extraction, so future company research does not become a one-off chat artifact.

This is session-specific evidence for the class-level `startup-company-analysis` skill.

## Source pattern observed

The AKKA/Fideum material used this sequence:

1. **Why invest in the company?** — capital efficiency, founder/regulatory credibility, traction, valuation entry.
2. **Understanding the basics** — plain-English company explanation and “X for Y” analogy.
3. **Opportunity** — regulatory deadlines, market adoption inflection, incumbents unable to build quickly, institutional adoption catalysts.
4. **Solution** — product modules and workflows replaced.
5. **Technology** — architecture layers, APIs, compliance layer, deployment modes, IP/moat claims.
6. **Market** — TAM/SAM/SOM, target institutions, market drivers.
7. **Business model** — setup fees, platform fees, transaction fees, ACV, gross margin drivers.
8. **Business plan** — P&L, revenue trajectory, profitability path, capital efficiency, use of funds.
9. **Go-to-market / commercial traction** — expansion regions, sales team, client expansion, churn, contract values.
10. **Round size and goal** — raise size, valuation, ticket range, SPV/offer terms.
11. **Valuation calculation** — comparables, ARR/revenue multiple, forward multiple, peer discount/premium.
12. **Why this valuation makes sense** — bull case and explicit countercase.
13. **Notable investors** — existing investors, partners, awards, validation logos.
14. **Competitors** — direct competitors and valuation comparables kept separate.
15. **Exit strategy** — only if evidenced; otherwise list as diligence question.
16. **Risks / bottom line** — regulatory, revenue-quality, customer concentration, forecast, margin, technical/security, reputation, and SPV friction.

## User preference learned

When a reusable analysis structure emerges, save it in two places:

- **Runtime skill** for future execution.
- **Second Brain page** for browseable Obsidian memory and graph links.

Do not leave the structure only in the chat transcript.

## Second Brain mapping that worked

For investment-company research, the useful cluster was:

- Company entity: `2-areas/investment/<company>.md`.
- Investment-platform tracker: `2-areas/investment/startup-investment-<platform>.md`.
- Per-source summaries: `3-resources/summaries/YYYY-MM-DD-<company>-<source>.md`.
- Optional red-flag memo: `3-resources/summaries/YYYY-MM-DD-<company>-investment-concerns.md`.
- Skill mirror page: `3-resources/tools-software/gandalf-skills/<skill-name>.md` when Asif asks to save the workflow as a skill.
- Parent updates: `investment.md`, `Resources MOC`, `Gandalf Skills MOC`, `gandalf-skills`, `index.md`, and `5-journal/log.md`.

## Durable pitfalls

- Do not treat AKKA/deck/management numbers as verified facts.
- Keep ARR, revenue, MRR, GMV, booking value, and transaction volume separate.
- Reconcile conflicting forecast versions explicitly.
- If creating a skill from a company-analysis session, keep the skill class-level and place session-specific details in `references/`, not in the main skill body.
